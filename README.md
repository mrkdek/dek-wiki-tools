# DEK — инструменты для wiki

Готовый статический сайт для GitHub Pages. Сборка, Node.js и серверная часть не нужны.

## Что перенесено

Проверены все 30 статей оглавления https://teletype.in/@mrk_dek/PD 23 ноября 2026 года. Найдены три iframe; дополнительных вложенных iframe в их коде нет. Полный список проверенных статей — `audit.json`.

| Статья | Страница сайта | Высота iframe для начала |
| --- | --- | --- |
| Рабочие инструменты | `work-tools/?embed=1` | 1000 px |
| Настройка рабочего компьютера дизайнера | `computer-setup/?embed=1` | 1400 px |
| СЗ на перемещение | `transfer-memo/?embed=1` | 1300 px |

В `originals/` находятся полные исходные HTML-файлы, извлечённые из data URL и srcdoc. В рабочих версиях сохранена логика приложений, добавлены полноценная HTML-оболочка для формы, ссылки между страницами и embed-режим. JavaScript-библиотеки JSZip, SheetJS и PDF.js вместе с PDF worker сохранены в `assets/vendor/`. Google Fonts заменён системным шрифтовым стеком исходного приложения. Автора исходных инструментов и встроенные уведомления о лицензиях не удаляли.

## Публикация на GitHub Pages

1. Распакуйте ZIP. Загрузите **содержимое** папки `dek-wiki-tools` в корень выбранного репозитория: `index.html`, `.nojekyll`, папки приложений и `assets` должны лежать непосредственно в корне.
2. Откройте **Settings → Pages**.
3. В **Build and deployment → Source** выберите **Deploy from a branch**.
4. Выберите ветку с файлами (например, `main`) и папку **/ (root)**, нажмите **Save**.
5. Дождитесь адреса опубликованного сайта в разделе Pages. Обычно он имеет вид `https://USERNAME.github.io/REPOSITORY/`.

Все пути относительные: сайт работает и в корне домена, и внутри `/REPOSITORY/`. Файл `.nojekyll` отключает обработку Jekyll. Не добавляйте `X-Frame-Options: DENY/SAMEORIGIN` или CSP `frame-ancestors 'self'`, если будете переносить сайт на другой хостинг: они заблокируют встраивание в wiki.

Официальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Вставка в wiki

Откройте **опубликованную главную страницу** и выберите приложение в блоке «Вставка в wiki». Кнопка **Скопировать ссылку** выдаёт полный адрес на вашем домене. В статье добавьте блок **Embed** и вставьте адрес. Сайт сам определяет, что открыт внутри iframe, и убирает внешнюю навигацию; `?embed=1` делает то же при отдельном открытии.

Кнопка **Код iframe** нужна только для редакторов, принимающих HTML. Outline обычно принимает URL в блоке Embed, а не HTML-код. Для произвольного домена GitHub Pages поддержка embed зависит от настроек и версии вашей wiki. Если она отклонит URL, администратору нужно разрешить этот домен как источник embed. Это нельзя исправить HTML-кодом самого сайта.

Копирование требует разрешения `clipboard-write`, а скачивание в sandbox — `allow-downloads`. В генераторе кода они учтены. Если wiki не передаёт эти разрешения, используйте отдельное открытие ссылки или ручное копирование из полей. В примерах заданы стартовые высоты; при необходимости настройте высоту блока в wiki. Сайт отправляет `dek-tools:resize` родителю, но автоматическая высота работает только в хосте, который обрабатывает это сообщение.

### Отдельные инструменты набора

К `work-tools/?embed=1` можно добавить `&tool=...`:

| Значение | Инструмент |
| --- | --- |
| `everything` | Поиск в Everything |
| `typograph` | Редактор текста |
| `filecheck` | Проверка файлов |
| `designcheck` | Проверка макета |
| `rename` | Переименование |
| `imgconvert` | Конвертер изображений |
| `imgcheck` | Контроль изображений |
| `flatten` | Сбор файлов из папок и архивов |

При таком встраивании открывается только выбранный инструмент, без меню набора. Например: `https://USERNAME.github.io/REPOSITORY/work-tools/?embed=1&tool=imgconvert`.

## Данные и внешние сервисы

Формирование заявки и записки, конвертация и операции с изображениями/архивами выполняются в браузере. **Проверка орфографии** в редакторе текста и проверке документов использует исходный сервис **Яндекс Спеллер**: проверяемый текст отправляется на `speller.yandex.net`; для этой функции нужен интернет. Это также указано рядом с соответствующими инструментами. История Everything сохраняется в localStorage браузера.

Форма настройки содержит исходные корпоративные пути и название принтера, а шаблон записки — исходные реквизиты адресата. GitHub Pages обычно публикует сайт для посетителей интернета; наличие приватного репозитория само по себе не означает закрытый доступ к Pages. В этот комплект не добавлялись тексты остальных статей, авторизация wiki или файлы пользователей.

## Локальный просмотр

Из папки сайта выполните `python -m http.server 8000`, затем откройте `http://localhost:8000/`. Для воспроизводимой работы библиотек, буфера обмена и PDF worker используйте HTTP/HTTPS, а не двойной щелчок по HTML.

## Состав

- `index.html` — каталог, прямые ссылки и генератор embed.
- `work-tools/`, `computer-setup/`, `transfer-memo/` — самостоятельные страницы.
- `assets/` — стили, навигация и локальные библиотеки.
- `originals/` — извлечённый код без адаптаций.
- `audit.json` — результаты обхода всех статей и контрольные суммы исходников.
- `tools.json` — карта страниц.
- `THIRD_PARTY.md` — зависимости и лицензии.

Статьи Teletype и wiki при подготовке комплекта не изменялись.
